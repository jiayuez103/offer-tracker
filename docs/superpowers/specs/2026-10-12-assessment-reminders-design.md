# 测评 DDL 提醒（M3）设计

> 续 `2026-09-20-job-tracker-design.md`。本文只写这个功能改了什么，字段和术语沿用原 spec。

## 1. 要解决的问题

测评 / AI 面试的邀请邮件给的是**相对期限**（「收到后 5 天内」「within 3 business days」），不是一个具体时间。用户要自己换算、自己记，于是会忘。

现状的两个缺口：

1. 录入麻烦：要手算「5 天后是哪天」，再去投递记录里手动加日程。
2. 提醒太晚：概览只在事件开始前 48 小时内提示。邀请往往提前五天到，中间几天 Tracker 一声不吭。

目标：**粘贴邮件正文 → 自动算出截止时间 → 进日历，并在 Tracker 里一直可见，直到做完。**

## 2. 范围

做：邮件解析、粘贴录入界面、日历多次闹钟、概览「今天要做的」汇总、事件的「截止型 / 会议型」区分。

不做（YAGNI）：

- 连邮箱自动抓取（要 OAuth 和常驻拉取，隐私面也大）
- Mac 桌面通知（要常驻进程，关机即失效；手机提醒交给日历订阅）
- 插件侧的邮件解析（邮件在 Mac 邮件客户端里，不在浏览器）
- 不存邮件原文，只存解析结果和一句依据片段

## 3. 事件新增字段

`applications[].events[]` 增加三个字段，老数据缺这些字段时按默认值处理：

| 字段 | 含义 | 缺省 |
|---|---|---|
| `mode` | `deadline`（在此之前做完）/ `meeting`（准时出席） | `测评`、`笔试`、`AI面` 为 `deadline`，其余为 `meeting`（沿用现有 `TEST_TYPES`） |
| `windowStart` | 窗口开始时间（= 收到邮件的时刻），用于显示「5 天窗口还剩 2 天」 | 空 |
| `basis` | 期限依据的原文片段，便于核对换算对不对 | 空 |

`mode` 让「截止」与「出席」分开：AI 面试默认按倒计时提醒（「5 天内自己找时间做」），但约好了具体时间的 AI 面可以显式设成 `meeting`，按「明天有面试」提醒。

## 4. 邮件解析（`shared/invite.js`，纯函数）

```
parseInvite(text, { receivedAt, settings }) → {
  type,            // 测评 | 笔试 | AI面
  mode,            // 固定 deadline
  deadline,        // ISO；认不出时为空
  basis,           // 依据原文片段（≤ 60 字）
  windowStart,     // = receivedAt
  durationMin,     // 认不出为 0
  link,            // 考试链接
  company, position, // 猜测，可能为空
  confident,       // 期限是否可信
}
```

规则：

- **相对期限**：`X 天内` / `X 日内` / `within X days` → `receivedAt + X×24h`；中文数字「一～十」要认。
- **工作日**：`X 个工作日` / `within X business days` → 从收到的次日起数，跳过周六日，落在第 X 个工作日的 18:00（`homeTz`）。
- **绝对期限**：`2026年10月15日`、`10月15日`、`2026-10-15`、`Oct 15`，可带 `24:00 前` / `23:59`；只有日期没有时间就按当天 23:59。没写时区时：中文正文按 `settings.eventInputTz`（北京），英文正文按 `settings.homeTz`（洛杉矶）—— 预览里两个时区都列出来，算错了一眼能看见。
- 同时出现相对和绝对期限时，取**更早**的那个。
- **时长**：`约 60 分钟`、`60分钟`、`1 小时`、`35-40 minutes` → 取上限的分钟数。
- **类型**：测评 / 测试 / 线上测评 / assessment / pymetrics / games → `测评`；笔试 / online test → `笔试`；AI 面试 / AI interview → `AI面`。
- **链接**：优先含 `exam` / `invite` / `assess` / `test` / `interview` 的 http(s) 链接，否则取第一个链接。
- **公司**：把正文和现有投递记录的公司名互相包含匹配（中英文都试、忽略大小写），命中就用记录里的写法。
- 期限认不出时 `confident: false`、`deadline` 留空，界面标红让用户手填，**不猜**。

## 5. 录入流程

入口：「日程」页右上角「粘贴邀请」按钮，概览的汇总条右侧也放一个。点开是抽屉：

1. 粘贴邮件正文（纯文本，不存原文）。
2. 自动解析，给出预览：类型、截止时间（**两个时区都显示**）、时长、链接、依据片段。每项都能改。
3. 「挂到哪条投递」下拉：匹配到的记录排在最前，另有「新建一条」选项。
4. 匹配到现有记录且当前阶段早于「测评」时，默认勾选「把阶段推进到测评」，可取消。
5. 没有匹配时自动新建：`{company, position, stage: 'assessment', channel: '官网', status: 'active'}`，缺的信息事后补。
6. 保存：往该记录的 `events` 追加一条，走现有 `PATCH /api/applications/:id`。新建走 `POST` 再 `PATCH`。

解析在网页里直接调用 `shared/invite.js`（网页本来就直接 import `shared/`），**不加服务端路由**；将来插件要用时再加 `POST /api/parse-invite`。

## 6. 日历提醒

`shared/ics.js` 现在每个事件只支持一个闹钟（`alarmMinutes`），改成支持多个（`alarms: number[]`，单位分钟）：

- `mode: 'meeting'`：`[60]`（不变）
- `mode: 'deadline'`：`[1440, m]`，其中 `m` = 截止当天 09:00（`homeTz`）距截止时间的分钟数；若截止时间本身早于当天 09:00（例如凌晨 2:42），`m` 取 `120`。

订阅链接不变，用户订阅一次，以后新增的测评自动带两次闹钟。

## 7. Tracker 里的提醒

**概览「今明两天」**：页面顶部一条，列今明两天要处理的事 —— 到期的截止型事件、今天截止的网申、今明的面试。没有内容时整条不显示。它复用 `actionItems` 的结果筛选，不另起一套规则。

**去掉 48 小时门槛**：`actionItems` 对 `mode: 'deadline'` 的未完成事件一直提示：

| 情况 | 文案 | 排序 |
|---|---|---|
| 剩余 > 48 小时 | `测评还剩 3 天` | 和网申截止同级 |
| 剩余 ≤ 48 小时 | `测评还剩 9 小时` | 最前 |
| 已过期未完成 | `测评已过期 2 天` | 最前 |

有 `windowStart` 时，文案后面补「窗口共 5 天」。

## 8. 测试

- `shared/invite.js`：各种期限写法（中文数字、工作日跨周末、绝对日期、相对与绝对同时出现）、时长、类型、链接、公司匹配、认不出时 `confident: false`。用例取自真实邀请邮件的句式，公司名一律换成「示例公司」。
- `shared/ics.js`：截止型事件生成两个 `VALARM`；截止时间在凌晨时退化成提前 2 小时。
- `shared/domain.js`：`actionItems` 对远期 / 近期 / 已过期截止事件的文案与排序；老数据（没有 `mode`）按类型推断。
- 网页：粘贴 → 预览 → 保存的完整流程在内置浏览器里走一遍，含「新建记录」和「挂到现有记录」两条路径。

## 9. 已知限制

本地工具在 Mac 关机时不会提醒。真正能在手机上叫醒用户的是**苹果日历订阅**，Tracker 里的汇总只在打开时可见。所以日历订阅是主力，汇总是补充。
